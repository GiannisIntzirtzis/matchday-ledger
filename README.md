# Matchday Ledger

Προσωπικό dashboard για διαιτητές ποδοσφαίρου, για την καταγραφή κάθε αγώνα: αμοιβές, κρατήσεις, έξοδα, βαθμολογίες (αυτοαξιολόγηση & παρατηρητή), κάρτες, φωτογραφίες φύλλου αγώνα, και παίκτες που ξεχώρισαν — όλα σε ένα σημείο, με γραφήματα και στατιστικά.

Χτίστηκε ως portfolio project κατά τη μετάβαση από SOC Analyst σε Data Engineer, αλλά λύνει και ένα πραγματικό, προσωπικό πρόβλημα καταγραφής σεζόν.

## Τι κάνει

- **Καταγραφή αγώνων** — κατηγορία (Ανδρικό / Υποδομές / Φιλικά / Κύπελλο), διοργάνωση (cascading dropdown ανάλογα την κατηγορία), γήπεδο, ρόλος, ομάδες, αποτέλεσμα
- **Οικονομικά** — αμοιβή, αυτόματος υπολογισμός κράτησης 10% (ΕΠΣΑ + Ένωση, μηδενικό για φιλικά), έξοδα μετακίνησης, καθαρό κέρδος
- **Αξιολόγηση** — αυτοαξιολόγηση, βαθμολογία παρατηρητή, κίτρινες/κόκκινες κάρτες
- **Φωτογραφίες φύλλου αγώνα** — έως 4 ανά αγώνα, μόνο όταν ο ρόλος είναι Διαιτητής, αποθηκευμένες ιδιωτικά ανά χρήστη
- **Παίκτες που ξεχώρισαν** — θετική/αρνητική εντύπωση, με σχόλιο
- **Γραφήματα** — καθαρό κέρδος στον χρόνο, αγώνες ανά διοργάνωση (ανά ρόλο), κατανομή ρόλων
- **Tabs, αναζήτηση, φίλτρα** — ανά κατηγορία, διοργάνωση, ή ελεύθερο κείμενο σε όλα τα πεδία
- **Λογαριασμοί χρηστών** — κάθε διαιτητής βλέπει μόνο τα δικά του δεδομένα (Row Level Security)
- **Προφίλ** — όνομα, σχολή διαιτησίας, κατάσταση αξιολόγησης, στοιχεία επικοινωνίας
- **Admin ρόλος** — read-only προβολή όλων των χρηστών και των αγώνων τους (π.χ. για χρήση από Ένωση Διαιτητών)

## Τεχνολογίες

- **Frontend**: HTML, CSS, vanilla JavaScript (χωρίς framework/build step)
- **Charts**: [Chart.js](https://www.chartjs.org/)
- **Backend**: [Supabase](https://supabase.com/) — PostgreSQL, Authentication, Storage, Row Level Security

## Τοπική εκτέλεση

1. Κλωνοποίησε το repo
2. Δημιούργησε ένα δωρεάν Supabase project
3. Τρέξε το [`schema.sql`](schema.sql) στο SQL Editor του Supabase project σου
4. Δημιούργησε storage bucket `fixture-photos` (private) — δες οδηγίες μέσα στο `schema.sql`
5. Αντικατέστησε το `SUPABASE_URL`/`SUPABASE_KEY` στο `js/app.js` με τα δικά σου (Project Settings → API)
6. Άνοιξε το `index.html` μέσω ενός τοπικού server (π.χ. VS Code Live Server extension) — **όχι** απευθείας ως `file://`, δεν λειτουργεί το auth/storage έτσι

## Σχεδιαστικές αποφάσεις

- Το πραγματικό "κλείδωμα" δεδομένων γίνεται μέσω **Row Level Security** στη βάση, όχι μόνο στο frontend — έτσι τα δεδομένα παραμένουν προστατευμένα ακόμα κι αν κάποιος παρακάμψει το UI.
- Ο admin ρόλος έχει **μόνο read access** σε δεδομένα άλλων χρηστών, ποτέ write/delete — μειώνει το ρίσκο, αρκεί για συγκεντρωτική εποπτεία.
- Η κράτηση 10% υπολογίζεται πάντα **δυναμικά** από την αμοιβή, δεν αποθηκεύεται σαν ξεχωριστό, χειροκίνητο πεδίο — αποφεύγει ασυμφωνίες.
